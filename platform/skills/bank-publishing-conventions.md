# 아톰은행 퍼블리싱 규약 (Skill · 화면 생성 에이전트 필수 준수)

이 문서는 생성 코드가 **반드시** 따라야 하는 규칙이다. "권장"이 아니라 검증 게이트와 리뷰어가 확인하는 기준이다.
규칙 번호(P-x)를 코드 주석에 적을 필요는 없지만, 위반 시 재생성 사유로 인용된다.

## P-1 레이아웃 그리드

- 화면은 위에서 아래로 **PageHeader → 조회 조건(선택) → 결과 영역 → 액션 영역** 순서로 배치한다.
- 컨테이너는 12컬럼 그리드를 전제한다. 간격은 8px 배수만 사용한다 (`8, 16, 24, 32`).
- 하나의 화면에는 **primary 버튼 1개**만 둔다 (예: `조회`). 나머지는 secondary/ghost.
- 액션 버튼은 결과 영역 **우측 하단**에 정렬하고, 파괴적 동작(삭제·취소)은 왼쪽 끝에 분리한다.
- 결과 표가 있는 화면은 표 위에 `총 N건` 요약을 표시한다. 건수는 데이터 배열의 `length`에서 계산하고 하드코딩하지 않는다.

## P-2 금액 표기

- 금액은 **천 단위 콤마 + '원'** 으로 표기한다: `1,234,567원`. `toLocaleString('ko-KR')`을 사용한다.
- 억/만 단위 축약은 요약 지표에만 허용하고 표 셀에는 원 단위 전체 금액을 쓴다.
- 금액·비율·건수 등 **모든 숫자 셀은 우측 정렬**, 텍스트 셀은 좌측 정렬한다.
- 음수는 `-1,000원`으로 표기하고 빨간색만으로 구분하지 않는다 (색 외에 부호를 반드시 함께 표기).
- 금리는 소수점 둘째 자리까지 `%`를 붙인다: `3.25%`. 한도는 `원` 단위로 표기한다.
- **화면 코드가 금액·금리·한도 숫자를 새로 계산하거나 만들어내지 않는다.** 전달받은 데이터 값을 포맷만 한다 (SPEC §12.2).

## P-3 날짜·시간 표기

- 날짜는 `YYYY.MM.DD` (예: `2026.09.02`), 일시는 `YYYY.MM.DD HH:mm`.
- 기간은 `2026.09.01 ~ 2026.09.30` 처럼 물결표 앞뒤에 공백을 둔다.
- 표 헤더에 단위나 형식을 표기한다: `신청일 (YYYY.MM.DD)`, `대출금액 (원)`.

## P-4 상태 배지 색 규칙

Badge 컴포넌트의 `tone` 값만 사용한다. 임의 색상 코드 금지.

| 업무 상태 | 배지 라벨 | tone |
|---|---|---|
| 승인 / 완료 / 정상 | `승인` | `success` |
| 심사중 / 진행중 / 대기 | `심사중` | `warning` |
| 반려 / 거절 / 오류 | `반려` | `danger` |
| 보류 / 취소 / 해당없음 | `보류` | `neutral` |
| 안내 / 참고 | `안내` | `info` |

- 배지 색만으로 의미를 전달하지 않는다 — 라벨 텍스트가 항상 함께 보인다 (KWCAG 5.4.1).

## P-5 문구·용어

- 모든 사용자 노출 문구는 **한국어**다. 버튼 라벨은 동사형 2~4자: `조회`, `초기화`, `승인 요청`, `엑셀 저장`.
- 필수 입력 항목은 레이블 뒤에 `*`를 붙이고, 화면 상단에 `* 표시는 필수 입력 항목입니다.` 안내를 둔다.
- 빈 결과 문구는 `조회 결과가 없습니다.`, 로딩 문구는 `조회 중입니다…`.
- 오류는 화면 상단 Alert(`kind="error"`)로 표시한다. 인라인 오류는 해당 FormField의 `error`로 전달한다.

## P-6 금지 표현 (컴플라이언스)

다음 표현은 어떤 문구에도 넣지 않는다.

- 수익·성과 단정: `확정`, `보장`, `무조건`, `최고 수익`, `반드시 오른다`, `손실 없음`
- 투자 권유성 문구: `지금 가입하세요`, `놓치면 후회`, `강력 추천`
- 실제 은행·상품·규정 명칭 (SPEC §12.7) — 상품명은 가상 명칭(`안심전세대출 II` 등)만 사용
- 개인식별정보 원문: 실명·주민번호·계좌번호·전화번호 전체를 표시하지 않는다. 표시가 필요하면 마스킹 형태(`김*수`, `110-***-****`, `CUST-…` 토큰)로만 표기하고, 그 값은 props로 받은 데이터만 사용한다.

## P-7 코드 규약

- 컴포넌트는 Registry **승인 컴포넌트만** 사용한다. 승인 목록에 없는 UI 요소가 필요하면 시맨틱 HTML(`<section>`, `<p>`, `<ul>`)로 대체하고 새 컴포넌트를 만들지 않는다.
- 샘플 데이터는 파일 상단에 `const SAMPLE_ROWS = [...]` 상수로 두고 **합성 값**임을 주석(`// 합성데이터`)으로 표시한다. 3~5행으로 제한한다.
- 이벤트 핸들러는 콘솔 출력이나 상태 변경만 한다. 네트워크 호출·저장소 접근 코드를 쓰지 않는다 (SPEC §12.10).
- 인라인 `style`은 CSS 변수 참조(`var(--…)`)나 정렬 지정(`textAlign`) 정도만 허용한다. 색상 hex 하드코딩 금지.
