# 이 책의 대상 독자와 읽는 법

::: tip 이 장에서 얻는 것
- 이 책이 누구를 위해 쓰였는지, 어떤 지식을 전제하는지 확인한다
- 6대 통증점 매핑을 통해 필요한 챕터로 바로 진입하는 방법을 익힌다
- 이 책이 다루지 않는 것과 시간이 지나면 낡을 수 있는 부분을 미리 안다
:::

## 왜 문제가 되는가

Agentic AI에 관한 자료는 대부분 "에이전트 하나를 어떻게 만드는가"에 답한다. 이 책은 그 질문에 답하지 않는다. 이 책의 질문은 "**에이전트를 만드는 에이전트**를 여러 팀·여러 비개발자가 안전하게 쓸 수 있게 운영하려면 무엇을 결정하고, 무엇을 켜고, 무엇을 계측해야 하는가"다.

## 핵심 개념

### 대상 독자

이 책은 AWS 기반 Agentic AI **메타플랫폼**을 설계·운영하는 플랫폼 엔지니어를 위해 쓰였다. Kubernetes, IAM, OAuth, 벡터 검색의 기초 개념은 이미 안다고 가정한다. "LLM이란 무엇인가", "벡터 임베딩이란 무엇인가" 같은 초심자 설명은 이 책에 없다.

이런 독자를 가정한다:
- 이미 하나 이상의 LLM 기반 서비스를 프로덕션에 올려본 적이 있다.
- 지금은 "에이전트 하나"가 아니라 "여러 팀이 에이전트를 만들고 운영할 수 있는 플랫폼"을 고민하고 있다.
- AWS Bedrock/AgentCore를 주요 배포 대상으로 검토 중이거나 이미 사용 중이다.

### 읽는 법

1. 처음 읽는다면 [6대 통증점](/00-intro/six-pain-points)에서 시작해 지금 가장 아픈 문제에 대응하는 Part로 진입한다.
2. 플랫폼을 처음부터 설계한다면 [메타플랫폼 전체 그림](/00-intro/meta-platform-overview) → Part 10(AgentCore 심화) → Part 9(권한 제어) 순으로 읽는 것을 권한다.
3. 각 챕터는 독립적으로 읽을 수 있게 설계됐다 — 필요한 배경지식은 교차 링크로 연결되어 있다.

### 이 책의 한계

::: warning 반드시 배포 전 재확인
AgentCore는 빠르게 진화 중이다. 가격·쿼터·TTL·최소 토큰은 리전·모델·시점에 의존한다. 본문의 수치는 2025~2026년 기준이며 **배포 전 최신 pricing/quota 페이지로 재확인해야 한다.** 특히 AgentCore Policy, Identity OBO, Evaluations는 이 책 작성 시점 기준 신규 또는 예정 기능이며 GA 일정·세부 스펙이 바뀔 수 있다.
:::

- **단일 vs 멀티에이전트는 미정착 영역이다.** Anthropic의 멀티에이전트 우위 보고는 내부 리서치 평가·특정 breadth-first 태스크에 한정되며 반례가 존재한다([Part 1](/01-agent-design/single-vs-multi-agent) 참고). 일반화하지 말 것.
- **context rot 수치는 태스크·모델 쌍에 의존한다.** 특정 모델·특정 컨텍스트 길이에서 관측된 저하가 다른 조합에 그대로 적용되지 않는다([Part 5](/05-context/context-rot) 참고).
- **임베딩 MTEB/BEIR 지표와 리랭킹 개선율은 특정 데이터셋 결과다.** 자체 도메인·한국어 데이터로 반드시 재측정해야 한다([Part 6](/06-vector-search/) 참고).
- **벤더/연구 벤치 수치(캐시 히트율, 공격 성공률 등)는 프로덕션 값과 다를 수 있다.**
- **비공식 출처(개인 블로그 등)로 보강한 구현 디테일은 공식 문서로 교차확인이 필요하다.** 본문에서 `⚠️ 비공식 출처 기반` 블록으로 표시했다.
- **한국 규제 관련 내용(Part 12)은 법률자문이 아니다.** 구체적 적용은 컴플라이언스·법률 전문가 확인이 필수다.

## 결정 표

| 상황 | 선택 | 이유 |
|---|---|---|
| 지금 특정 증상(느림/부정확/비용/컨텍스트/스케일/권한)을 겪고 있다 | [6대 통증점](/00-intro/six-pain-points)에서 매핑된 Part로 바로 이동 | 개념을 순서대로 읽을 시간이 없을 때 가장 빠른 경로 |
| 플랫폼을 처음부터 설계한다 | Part 0 → Part 10 → Part 9 → Part 4/5 순으로 읽기 | 전체 그림과 인프라 계약을 먼저 이해해야 개별 통증점 해법이 맞물린다 |

## 실패 모드

| 증상 | 근본 원인 | 확인 방법 | 해결 |
|---|---|---|---|
| 책의 수치를 그대로 설계 근거로 인용했는데 실제와 다름 | AgentCore/Bedrock 가격·쿼터가 책 작성 이후 변경됨 | 각 수치의 출처 URL을 열어 최신 값 확인 | 배포 전 항상 공식 pricing/quota 페이지 재확인 |
| 멀티에이전트 도입 후 비용만 늘고 성능 향상이 없음 | "미정착 영역" 경고를 무시하고 한쪽 주장만 적용 | 자체 태스크가 breadth-first·독립 병렬 탐색에 해당하는지 확인 | [Part 1 단일 vs 멀티 에이전트](/01-agent-design/single-vs-multi-agent) 결정 표 재검토 |

## 안티패턴

- ❌ 이 책의 수치를 최신 공식 문서 확인 없이 그대로 설계 문서에 인용한다 → ✅ 출처 URL을 열어 현재 값을 재확인하고 인용한다.
- ❌ Part 1을 읽지 않고 멀티에이전트를 기본값으로 채택한다 → ✅ 결정 표에 따라 태스크 특성을 먼저 판단한다.
