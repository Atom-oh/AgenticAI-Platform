# 외부 산출물 파일 반입

기준일: 2026-09-11. 아래 계약을 바탕으로 **파일·스킬 작업실**을 구현했다.
새 작업실의 파일 반입·규칙 승인·브라우저 검증과 기존 텍스트 자산 등록은 서로 다른 흐름이다.
배포 검증 결과는 플랫폼 README에 기록하며, 조작 순서는 [디자이너 작업실 사용법](./studio-designer-guide)을 따른다.

## 운영 전제

- 사용자 확인에 따라 **3호망에서도 Figma 접속이 불가**하다. 이전의 “3호망에서 Figma 작업·다운로드” 전제를 대체한다.
- 시작점은 외부에서 제작·전달받은 HTML·PNG·JPG·SVG·FIG·PDF 등의 파일이다. 제작 도구를 Figma로 제한하지 않는다.
- 조직의 정해진 반입 절차를 거친 파일을 Studio에 업로드한다. Studio의 형식 검사는 조직의 반입 승인이나 보안 평가를 대신하지 않는다.
- Figma 계정·API 토큰·플러그인 설치를 Studio 사용의 선행 조건으로 요구하지 않는다.
- 외부 원본 URL은 제공된 경우 출처로만 기록한다. 원본·누락 리소스의 자동 다운로드, 우회 연결 또는 외부 변환 서비스 호출을 하지 않는다.
- LLM은 허용된 Bedrock, 사내 데이터·도구는 제공 가능한 사내 MCP를 사용한다.

## 디자이너의 입력 흐름

1. **파일 추가:** 반입된 파일을 선택한다. 처음부터 Manifest나 JSON을 직접 작성하게 하지 않는다.
2. **원본 확인:** 파일명·형식·크기와 지원 가능한 미리보기를 보여준다. 파일별로 오류를 표시하고 정상 파일까지 사라지게 하지 않는다.
3. **용도 지정:** 화면 기준 이미지, 화면 시안, 업무 설명, 아이콘, 원본 보관 등으로 분류한다. 자동 제안은 사용자가 확인한다.
4. **반입 저장:** 프로젝트에 원본을 보관하고 반입 ID·해시·버전을 만든다. 업로드 완료와 해석 완료를 별도 표시한다.
5. **화면·규칙 확인:** 해석 가능한 화면이나 문서를 선택하고 AI가 추정한 화면 역할·흐름을 검토한다. 필요한 조건은 담당자가 보완한다.
6. **생성·검수:** 확정된 입력과 내부 기준의 버전을 고정해 기존 생성·피드백·재검증 루프로 연결한다.

파일만 있는 상태에서 버튼의 의미나 성공·실패·뒤로가기 조건이 모두 확정됐다고 처리하지 않는다.
설명 없는 이미지도 시각 참고 자료로 수용하되, 업무 규칙까지 확보한 것으로 표시하지 않는다.

## 형식별 목표 지원

| 형식 | 첫 반입 단계의 목표 | 별도로 확인할 내용 |
|---|---|---|
| HTML·HTM | 원본 보관, 스크립트 실행과 외부 요청을 차단한 파생 미리보기, 추출 가능한 DOM·문구 표시 | CSS·이미지·폰트 등 누락 리소스. 외관 확인을 실제 동작 검증으로 표시하지 않음 |
| PNG·JPG·JPEG | 원본 보관, 화면 미리보기·크기 표시, 화면 기준 이미지로 선택 | OCR·AI의 텍스트/구조 해석은 추정이며 컴포넌트·조건 정보와 구분 |
| SVG | 원본 보관, 격리된 이미지 미리보기, 아이콘/벡터 자산으로 분류 | 스크립트·외부 참조를 실행하지 않음. XML을 앱 DOM에 그대로 삽입하지 않음 |
| PDF | 원본 보관, 지원 가능한 페이지 미리보기·선택, 추출 가능한 텍스트 표시 | 페이지별 추출 실패·암호화·미지원 상태 표시. 링크·첨부·동작을 자동 실행하지 않음 |
| FIG | 원본 보관, 파일·반입 정보 표시 | **내부 화면 해석·렌더링은 미지원으로 시작.** 함께 받은 PNG/PDF가 있으면 연결하고, 없으면 미리보기 없음으로 표시 |
| JSON·MD·TXT | 기존 텍스트 자산 입력 유지, 업무 설명·규칙과 연결 | 구문 유효성과 업무 규칙의 정확성은 별도 판정 |

HTML과 로컬 리소스를 함께 전달받으면 누락 없이 연결할 수 있는 명시적인 파일 대응 정보가 필요하다.
ZIP 자동 해제·임의 경로 탐색은 첫 단계의 완료 조건에 포함하지 않는다.

## 보관·해석·검증 상태

세 상태를 따로 보존한다.

- **반입 상태:** 대기 / 업로드 중 / 보관 완료 / 실패.
- **해석 상태:** 미처리 / 해석 중 / 완료 / 일부 지원 / 미지원 / 실패.
- **UX 검증 상태:** 미검증 / 검증 중 / 통과 / 수정 필요 / 미판정.

예를 들어 FIG 파일은 “보관 완료 · 해석 미지원 · UX 미검증”이 될 수 있다.
이 상태를 “파일 업로드 실패”나 “디자인 검증 통과”로 바꾸지 않는다.

## 원본과 버전

Studio가 반입 ID, 반입 버전, 원본 파일명·크기·해시, 반입 시점·담당자, 파일 간 연결, 처리 상태를 기록한다.
외부 제작 도구의 원본 버전·Figma fileKey·nodeId는 실제 제공된 경우에만 기록하고 없으면 미확인으로 둔다.
원본 버전과 Studio 반입 버전은 같은 값으로 간주하지 않는다.

원본 바이트는 보존하고 미리보기·추출 텍스트·AI 해석은 파생 산출물로 관리한다.
다시 업로드한 파일은 새 반입 버전으로 연결하고 이전 원본·검수·승인 이력을 덮어쓰지 않는다.
AI가 추정한 흐름은 사용자 확인 전까지 검증 기준으로 확정하지 않는다.

반입 원본은 공개 웹 산출물 경로에 저장하지 않는다. 인가된 저장소와 다운로드 경로를 사용하고,
원본의 앱 내 자동 실행을 막으며, 미리보기에서도 외부 네트워크 요청이 발생하지 않는지 확인한다.

## 첫 완료 기준

- 대상 형식의 파일을 반입 저장한 뒤 다시 조회·다운로드할 수 있고 원본 해시가 일치한다.
- 확장자만으로 파일 형식을 신뢰하지 않으며 손상·불일치·과도한 크기를 명확하게 안내한다.
- 각 파일에 원본 보관과 미리보기·해석의 지원 상태가 별도로 나타난다.
- HTML/SVG 미리보기의 스크립트·외부 요청 차단을 브라우저에서 검증한다. PDF도 외부 동작 없이 지원 범위만 처리한다.
- FIG 해석 미지원 및 이미지에서 확보하지 못한 흐름·컴포넌트 정보를 숨기지 않는다.
- 파일 추가·해제·재반입·중복·부분 실패 시 어떤 파일이 최종 입력인지 사용자가 확인할 수 있다.
- 파일을 올렸다는 이유로 UX 규칙 검증이나 사내 컴포넌트 매핑이 완료된 것으로 표시하지 않는다.

일반 파일용 원본 저장·조회는 별도 인증 HTTP API와 비공개 저장소를 사용한다.
기존 텍스트 자산 등록이나 공개 시안 게시 경로에 반입 원본을 올리지 않는다.
스킬 문서·토큰·CSS는 작업 지침과 디자인 데이터로 사용하며 서버 프로그램으로 실행하지 않는다.
