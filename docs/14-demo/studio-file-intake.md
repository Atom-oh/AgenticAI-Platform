# 외부 산출물 파일 반입

기준일: **2026-09-11**. 파일 반입은 React 공동 디자인 작업실의 입력 단계다.
최종 전달 단위는 검증한 React 소스와 배포용 번들이며, 반입 HTML은 참고 자료 또는 원본 검사 대상으로 유지한다.
조작 순서는 [디자이너 작업실 사용법](./studio-designer-guide)을 따른다.

## 운영 경계

- 외부 제작·전달 파일은 조직의 정해진 반입 절차를 거쳐 금융망 Studio에 업로드한다. 제작 도구를 Figma로 제한하지 않는다.
- Studio는 Figma 계정·API 토큰·플러그인을 요구하지 않으며, Figma·CDN·외부 폰트·누락 리소스를 자동으로 가져오지 않는다.
- 외부 원본 URL은 출처 정보다. 다운로드·우회 연결·외부 변환 서비스 호출을 허용하는 지시로 사용하지 않는다.
- AI 제안·생성·수정은 기존 경계 검사와 가드레일을 거치는 허용된 Bedrock 연결을 사용한다.
  사내 도구 연결은 실제 제공된 사내 MCP 계약만 대상으로 한다.
- 파일 형식 검사와 화면 검증은 조직의 반입 승인 절차를 대신하지 않는다.

## 저장할 공간부터 선택

개인 작업실의 원본은 개인 범위에 남는다. 공동으로 사용할 자료는 선택한 프로젝트에 반입한다.
프로젝트 ID만으로는 접근할 수 없으며 매 요청에서 현재 참여 권한을 확인한다.
개인 자료를 프로젝트로 자동 공개하거나 기존 초안을 일괄 이관하지 않는다.

한 파일은 최대 **50MiB**이며 화면이 분할 전송과 재시도를 처리한다.
사용자는 파일 추가 → 용도 확인 → 비공개 보관 → 해석 상태 확인 순서로 작업한다.
생성 기준으로 선택할 수 있는 자산은 최대 20개이며, 공동 작업에서는 자동 포함되는 게시 지침도 이 한도에 포함된다.

## 현재 형식별 처리

| 형식 | 제공하는 처리 | 해석·검증의 한계 |
|---|---|---|
| HTML·HTM | 원본 보관, 제한된 파생 미리보기, 문구·외부 참조 분석, 별도의 원본 브라우저 검사 | 원본 미리보기와 동작 검증은 별도. React 소스로 자동 변환됐다는 뜻이 아님 |
| CSS | UTF-8 스타일 참고 자료와 외부 참조 분석, 원본 HTML 검사 시 선택한 로컬 파일 연결 | TXT로 이름을 바꿀 필요 없음. React 컴포넌트의 고정 스타일을 덮어쓰지 않음 |
| PNG·JPG·JPEG | 원본 보관, 이미지·크기 확인, 지원 가능한 OCR·AI용 파생 이미지, 화면 비교 기준 | 이미지 자체가 업무 조건이나 React 컴포넌트 구현을 증명하지 않음 |
| SVG | 원본 보관, 안전한 이미지 미리보기·로컬 이미지 사용 | 스크립트·외부 참조를 실행하거나 XML을 앱 화면에 그대로 삽입하지 않음 |
| PDF | 원본 보관, 제한된 페이지 미리보기·텍스트 추출 | 암호화·손상·페이지 한도·부분 해석을 표시. 링크·첨부 프로그램을 자동 실행하지 않음 |
| FIG | 원본 보관·조회·다운로드 | 내부 화면 해석·렌더링·프로토타입 추출은 미지원 |
| JSON·MD·MARKDOWN·TXT | 텍스트 자료·업무 가이드·작업 지침으로 반입 | 설명 자료이며 실제 React 컴포넌트 코드나 승인된 테스트를 대신하지 않음 |

PNG 원본과 이미지 자산의 투명도는 유지하며 OCR·모델 입력용 변환은 별도 파생 자료다.
PDF와 이미지의 페이지 선택은 **첫 페이지가 1**이다.

HTML과 함께 받은 CSS·이미지는 선택된 파일 안에서 고유한 로컬 대응을 확인할 때만 검사본에 연결한다.
중복 파일명, 외부 URL, 지원하지 않는 참조는 누락·해결 필요 상태로 남긴다.
ZIP 전체 패키지 해석, 임의 경로 탐색, FIG의 실제 React 컴포넌트 매핑은 완료 범위에 포함하지 않는다.

## React 기준과 참고 파일의 차이

현재 기준은 실제 코드·타입·토큰을 가진 **플랫폼 기본 React 컴포넌트 15종**이다.
고객의 사내 React 패키지는 아직 제공되지 않았다. 컴포넌트 HTML, CSS, 이미지, MD를 올려도 이 패키지를 대체하지 않는다.
업로드 자료의 package.json 스크립트나 플러그인, 서버 명령은 실행하지 않는다.

기획 담당자가 상품 지침을 게시하면 불변 지침 원문과 비공개 가이드 자산, 상품·조건·절차·안내의 온톨로지를 함께 저장한다.
공동 규칙은 이 게시 지침을 자동 포함한다. 게시 지침은 일반 파일처럼 재반입·사용 제외하지 않고 새 지침 버전을 게시해 변경한다.

## 상태를 구분해서 읽기

| 단계 | 확인하는 것 |
|---|---|
| 반입 | 원본 전송·보관의 성공 또는 실패 |
| 해석 | 미리보기·텍스트·OCR의 완료, 일부 지원, 미지원 또는 실패 |
| 시안 검증 | 승인한 규칙으로 실제 화면을 검사한 통과·실패·미판정 |
| 릴리스 | 승인된 React 소스의 동일성·재빌드·브라우저 재검증 결과 |

FIG는 **보관 완료 · 해석 미지원 · 시안 미검증**으로 남을 수 있다.
이 상태를 업로드 실패나 디자인 검증 통과로 바꾸지 않는다. 원본 HTML 검사 통과도 React 릴리스 승인이 아니다.

## 원본·버전·다운로드

원본 바이트와 파일 해시를 보존한다. 미리보기·추출 텍스트·검사본은 원본과 별도로 관리한다.

- **반입 버전:** 같은 파일 계보에 새 원본을 반입한 순서(`importRevision`).
- **내부 수정 번호:** 전송·상태 변경을 안전하게 처리하기 위한 값(`version`). 반입 횟수가 아니다.
- **제작 도구 원본 버전:** 실제 제공된 경우에만 확인할 수 있으며 없으면 미확인이다.

이전 원본·검수·승인 이력을 새 자료로 덮어쓰지 않는다. 사용 목록에서 제외하는 작업도 원본 삭제가 아니다.
원본은 비공개 저장소와 인증된 다운로드 경로로 제공하며, 공개 웹 버킷에 게시하지 않는다.
최종 React 소스 ZIP·배포용 dist·검수 근거 역시 비공개로 보관한다.

## 확인된 상태와 남은 확인

최신 백엔드 업데이트는 **AWS UPDATE_COMPLETE**다.
라이브 합성 자료 **HTML·CSS·SVG·PNG·JPG 5종**의 반입과 인증 다운로드 후 원본 해시 일치를 확인했다.
이 결과를 모든 입력 파일의 의미 해석이나 화면 동작 통과로 확대하지 않는다.

라이브 Astra 기준안+변형 2개와 Fable 새 UX 1개는 모두 2라운드에서 실제 React 타입·빌드·접근성·동작 검사를 통과했다.
이 실행에는 원본 이미지 기준을 지정하지 않아 시각 비교는 미수행이며, Figma 픽셀 일치 결과가 아니다.
실제 API에 연결한 새 UI의 FHD/QHD/WQHD 스테이징 확인도 통과했다. 새 프런트엔드는 아직 게시하지 않았으며
승인 후 AWS 재빌드·릴리스 검사는 진행 중이다. 고객 React 패키지와 Git 대상은 미제공·미설정 상태다.
전체 상태는 [구현 점검](./studio-implementation-review), 개발 계약은
`platform/workspace/CONTRACT.md`와 `platform/workspace/REACT_CONTRACT.md`를 따른다.
