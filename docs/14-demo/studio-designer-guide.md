# 디자이너 작업실 사용법

Studio의 **파일·스킬 작업실**에서 시작한다. Figma 계정·접속·플러그인이나 직접 작성한 JSON은 필요하지 않다.
외부에서 전달받아 조직의 정해진 반입 절차를 거친 파일을 준비한다.

## 1. 파일 준비

HTML 시안과 연결된 CSS, PNG·JPG·SVG, 업무 설명이나 스킬 문서를 함께 추가한다.
파일별 용도를 확인하고 **비공개 보관하기**를 누른다. 한 파일은 최대 50MiB다.
전송이 실패하면 같은 파일의 **전송 다시 시도**를 사용한다.

| 자료 | 권장 용도 |
|---|---|
| 화면 전체의 PNG/JPG | 화면 기준 |
| 버튼·아이콘·로고·컴포넌트 HTML/SVG | 컴포넌트 |
| 색상·간격 등의 JSON 또는 CSS | 토큰 / 가이드 |
| SKILL.md 등 작업 지침 | 스킬 |
| 업무 흐름·금액·동의·오류 조건의 MD/TXT/PDF | 가이드 |
| 실행해 볼 HTML | 시안 / 프로토타입 |
| FIG | 원본 보관 |

원본은 그대로 보관한다. 미리보기·OCR·AI용 이미지는 별도 산출물이다.
PNG의 투명도는 미리보기와 컴포넌트 사용 시 유지한다.
FIG는 원본 보관만 지원하며, 내부 화면·프로토타입 해석은 지원하지 않는다.
PDF 페이지 수나 문서 분석량이 제한되면 파일에 일부 지원 상태와 이유가 표시된다.

**보관 완료는 UX 검증 통과가 아니다.** 이 단계에서는 모델을 호출하지 않는다.
스킬은 AI가 참고하는 작업 지침이며, 문서에 포함된 서버 명령·프로그램을 실행하지 않는다.

## 2. 규칙 확인·승인

사용할 파일을 선택하고 **규칙 확인·승인** 단계로 이동한다.
만들 화면을 설명하고 허용된 Bedrock 모델을 골라 AI에게 규칙을 정리하도록 요청한다.

예를 들어 다음과 같은 조작과 확인 단계가 만들어진다.

1. 납입금액에 `10000` 입력.
2. 다음 버튼 클릭.
3. 확인 화면에 같은 금액이 표시되는지 확인.
4. 필수 동의를 하지 않으면 제출할 수 없는지 확인.

문서의 실제 인용, AI의 추정, 직접 작성한 규칙을 구분한다.
잘못된 단계·기대값을 수정하고, 미정의 조건이나 일부만 해석된 자료의 적용 범위를 확인한다.
**규칙 저장 → 검토 확인 → 해당 버전 규칙 승인** 순서로 확정한다.
규칙을 수정하면 새 버전에는 이전 승인이 적용되지 않는다.

색상·글자 크기·간격 등은 **스타일 일치** 확인 단계로 검사할 수 있다.
원본 HTML 요소와의 자동 연결이 맞지 않으면 고급 요소 연결에서 확인할 수 있다.
생성 시안에는 검증 대상 식별자가 자동으로 들어가므로 기본 흐름에 CSS나 JSON 작성은 필요하지 않다.

## 3. 원본 검사 또는 AI 생성

**생성·검수·수정**에서 승인한 규칙을 선택한다.

- **반입 HTML 검사:** 선택한 HTML을 AI로 다시 만들지 않고 실제 브라우저에서 검사한다.
  원본 바이트는 보존하며 격리 정책과 선택된 로컬 CSS·이미지 연결을 적용한 검사본을 따로 저장한다.
- **AI 시안 생성:** 선택한 파일·스킬·가이드와 확정한 규칙을 사용해 실행 가능한 HTML을 만든다.
- **시안 3종:** 같은 규칙으로 다른 화면 구성을 만들고 각 시안의 검수 결과를 비교한다.

HTML의 상대경로가 선택한 CSS·이미지의 고유한 파일명과 연결되면 검사본에 포함된다.
외부 URL을 따라 파일을 다운로드하지 않는다. 같은 파일명이 여러 개이거나 지원하지 않는 참조가 있으면 표시하고 검증을 완료한 것으로 처리하지 않는다.

시작 화면을 이미지와 비교하려면 **반복 횟수와 시작 화면 비교 설정**에서 기준 이미지·페이지와 허용 오차를 정한다.
기준 이미지와 규칙의 화면 크기가 같아야 한다. 전체 화면 비교에는 불투명한 화면 이미지를 사용한다.
기준을 선택하지 않으면 **시각 비교 미수행**이다. 시작 화면 비교가 모든 화면·상태의 시각 검증을 뜻하지 않는다.

## 4. 근거를 보고 수정

실제 입력·클릭·체크·값 전달·상태·스타일을 브라우저에서 시험한다.
접근성, 브라우저 오류, 외부 요청, 선택한 시작 화면의 픽셀 차이도 확인한다.
실행하지 못한 항목이나 누락된 증거는 통과로 표시하지 않는다.

AI 생성에서는 실패 근거를 바탕으로 **동일한 규칙**에 대해 다시 생성·검사한다.
시간이나 반복 상한에 도달해도 자동 승인하지 않는다.
라운드를 선택해 실제 결과와 검수 기록을 보고, 보고 있는 라운드에 수정 지시를 줄 수 있다.

**통과한 동일 HTML·규칙 버전·검수 기록**을 확인한 뒤 시안을 승인하고 내려받는다.
원본 반입 파일, 검사·생성 HTML, 스크린샷, 차이 이미지, 검수 보고서는 구분해서 보존한다.

## 검증 범위

이 작업실의 결과는 **검토한 규칙에 대한 실행형 프로토타입의 검증**이다.
실제 은행 인증·거래 API, 제공되지 않은 사내 React 패키지, 원큐 제품 통합까지 검증한 것은 아니다.
금융·인증 결과는 모의 상태로 구현하며 실제 거래를 발생시키지 않는다.
새 패키지를 반입하거나 규칙을 바꾸면 해당 버전으로 다시 검증한다.
