# Design Studio — 디자이너 관점의 구현 점검

점검일: 2026-09-10. 사용자 제공 점검 기록, 현재 코드, Bedrock 실목록·호출, 이번 브라우저 테스트를 구분해서 판단했다.

배포 확인: Astra·Fable 모델 선택은 라이브에 반영됐다. Astra와 Fable 5.1로 실제 시안을 생성·저장했고,
AgentCore Runtime에서도 해당 모델의 응답을 확인했다. 테스트 시안은 승인하지 않았다.

## 이 장에서 얻는 것

**현재 제품은 디자인 초안 생성과 정적 검수를 돕는 도구다. 비개발자 디자이너가 반입부터 실제 제품 검증까지 혼자 완료하는 시스템은 아직 아니다.**
모델 선택과 일부 통합 오류를 고쳐도, 반입 패키지 해석·사내 컴포넌트 매핑·실제 동작 검증의 공백은 남는다.

## 확정된 운영 전제

- Figma 작업과 다운로드는 **3호망**에서 수행한다.
- 금융망 Studio는 사용자가 반입한 파일을 입력으로 받는다. Figma URL은 출처 메타데이터이며 자동 조회 대상이 아니다.
- 생성과 리뷰는 허용된 Bedrock 연결을 사용한다. 사내 데이터·도구는 실제 제공되는 사내 MCP 계약으로 연결한다.
- 이미지·폰트·아이콘·코드는 반입 파일이나 허용된 사내 저장소에서 해결한다.

Figma 직접 연결이나 외부 자동 동기화가 없는 것은 결함이 아니다.

## 왜 문제가 되는가

현재 사용자에게 필요한 것은 “어느 모델이 더 좋은가”보다 “어떤 파일을 올리고, 어떤 기준을 확인하고,
무엇을 승인해도 되는가”에 대한 일관된 안내다. 정적 시안 점수와 실제 동작 검증이 섞이면 디자이너가
잘못된 확신을 갖는다. 같은 화면을 보고 수정했는데 다른 라운드가 수정되는 문제는 피드백 루프 자체를 깨뜨린다.

## 확인한 수정 범위

| 항목 | 변경 내용 | 증거와 한계 |
|---|---|---|
| Astra·Fable 선택 | 공통 허용 목록, Studio 생성·수정·리뷰·프로세스와 에이전트 빌더에 연결 | Astra, Fable 5, Fable 5.1은 서울 리전 활성 프로파일 조회 및 게이트 경유 실제 호출 확인 |
| 모델 격리 | 호출별 모델을 고정하고 전역 기본 모델을 바꾸지 않음 | 서로 다른 모델의 동시 요청, 허용 목록 밖 모델 거부, PII 게이트 테스트 |
| 수정 원본 | 디자이너가 선택한 `baseRound`를 서버 저장 기록으로 확인한 뒤 사용 | R1을 보며 R2를 수정하는 문제에 대한 회귀 테스트 |
| 검수표 | 화면에 표시한 라운드의 검수표를 사용. 이전 기록이 일부 항목만 있으면 명시 | 신규 전체 검수표는 라운드별 별도 레코드에 저장, 이력 목록과 분리 |
| 통과·승인 | 미판정·리뷰 오류를 통과로 세지 않음. 통과 라운드를 점수보다 먼저 선택 | 서버에서도 같은 정적 검수 조건·해당 시안의 기록을 확인. 실제 기능 승인은 아님 |
| 이전 시안 | 원래 점수·승인 이력을 보존하고 이전 기준 기록으로 표시 | 새 기준으로 승인하려면 재검수 필요. 옛 갤러리 전체 이관은 미구현 |
| 프로세스 접근 | 플랫폼 로그인으로 실행, 구 Studio 토큰 의존 제거 | 공유 자산 등록은 아직 기존 레지스트리 인증 경로 사용 |
| 파일 반입의 첫 단계 | 로컬 JSON·Markdown·TXT를 읽어 등록 폼에 반영, 크기·형식 오류 안내 | 전체 `.fig`, ZIP, 이미지 패키지 해석이나 프레임 미리보기 기능은 아님 |
| 산출물 리소스 | 새 HTML에 외부 연결 제한 CSP 적용, 이미지·CSS 등 자동 로드 참조 검출 | 격리 브라우저에서 외부 요청 차단과 인라인 동작 확인. 완전한 코드 샌드박스 감사나 시각 검증을 뜻하지 않음 |
| 앱 진입·문구 | `#/agents`에서 `#/studio`로 안내, 정적 시안·동작 미검증 표시, 고급 설정 분리 | 디자이너는 에이전트를 먼저 만들 필요 없음 |
| 배포 보존 | 웹 업로드가 생성 시안까지 삭제하지 않도록 버킷 전체 `--delete` 제거 | 기존 시안·프로세스 산출물 보존 |

허용 모델은 Claude Sonnet 5, Claude Opus 5, GPT-6 Astra, Claude Fable 5.1, Claude Fable 5다.
기존 독립 Studio의 `/api/models`에는 이미 Astra·Fable이 포함되어 있었다. 모델 선택 누락은 통합판의 문제였다.
목록에 표시된다는 사실만으로 모든 에이전트·도구 조합의 품질을 보장하지 않는다.

## 디자이너의 실제 업무 기준으로 본 판단

| 업무 | 판단 | 남은 문제 |
|---|---|---|
| 화면 설명과 상품을 골라 초안 만들기 | 사용 가능 | 상품·업무 기준이 미리 준비되어야 함 |
| 모델을 바꿔 생성·수정하기 | 구현 범위에 포함 | 모델별 품질·비용의 조직 기준은 별도 운영 필요 |
| 지금 보고 있는 시안을 수정하고 근거 확인하기 | 통합 오류 보정 | 실제 위치·간격 보존 검증은 아직 없음 |
| 3호망 Figma 산출물을 반입해 바로 작업하기 | 불충분 | 현재 텍스트 자산 입력 수준. 패키지·프레임·리소스·버전 해석 없음 |
| 사내 승인 React 컴포넌트로 연결하기 | 입증 부족 | 실제 import·props·variant·토큰·버전 대응표와 미매핑 처리 필요 |
| 입력·인증·동의·분기 동작 검증하기 | 불충분 | 구조·문구 검사로 값 전달이나 진행 차단을 증명할 수 없음 |
| 이전 Studio 작업을 한곳에서 찾기 | 불완전 | 자산 조회 연결과 시안·부모 관계·승인 이력 이관은 별개 |
| 승인 후 제품으로 전달하기 | 아직 별도 검증 필요 | 정적 시안 승인, 기능 검증, 제품 통합 승인을 분리해야 함 |

## 실패 모드와 안티패턴

- 정적 스토리보드 점수를 실행 가능한 프로토타입의 품질 점수로 해석한다.
- 검수표를 불러오지 못했는데 “미충족 항목 없음”으로 표시한다.
- 이전 기준 점수를 새 검증 결과처럼 사용하거나 옛 사람 승인을 자동 승격한다.
- 원본에 없는 조건·전이를 AI가 추정했는데 승인된 PRD처럼 취급한다.
- 파일 선택 버튼이 있다는 이유로 전체 Figma 패키지 반입이 완성됐다고 설명한다.
- 외부 Figma 직접 연결을 금융망 제품의 필수 기능으로 다시 요구한다.

## 다음 구현의 우선순위

1. **반입 패키지 계약과 업로드:** Manifest·해시·반입 버전·프레임 이미지·로컬 리소스를 검사하고 누락·미지원 항목을 표시한다.
2. **사내 기준 매핑:** 원본 노드, 승인 PRD, SM 모델, 실제 React import·props·토큰 버전을 연결한다.
3. **필수 실행 게이트:** 입력값 변경이 후속 화면까지 이어지는지, 인증·동의 미완료 시 진행이 차단되는지 합성 데이터로 확인한다.
4. **시각·접근성 검증:** 실제 사내 UI 패키지와 승인된 기준 이미지로 비교한다. 구조 해시로 픽셀 일치를 대신하지 않는다.
5. **이력 통합과 재반입:** 기존 시안·승인·편집 부모 관계와 새 패키지의 변경 영향을 추적한다.

첫 완료 단위는 “네 개 모바일 프레임 전체를 그리기”가 아니라, **한 반입 패키지의 한 업무 경로를 사내 컴포넌트로 연결하고 정상·실패·뒤로가기·값 전달을 끝까지 검증하는 것**이다.
실제 금융 거래·인증 실행은 사용하지 않는다.

## 계측과 완료 체크

- 생성 완료 시간과 UX 승인까지의 시간을 따로 측정한다.
- 정적 검수 통과율, 미판정 종료율, 수정 중 회귀율, 승인 후 결함률을 구분한다.
- 승인에는 반입·규칙·컴포넌트·코드·검증 결과의 동일 버전 근거가 필요하다.
- 이번 테스트 결과를 실제 은행 React 저장소나 사용자 제공 Figma 파일의 기능 검증 결과로 재사용하지 않는다.

## 근거

- 사용자 제공 「Agentic AI / Design Studio 구현 점검」: 운영 전제·미팅 요구·기존/통합 서비스의 관찰·Figma 표본.
- `platform/engine/model_catalog.py`, `platform/engine/gate.py`: 허용 모델과 경계.
- `platform/studio/`, `platform/api/handlers/studio.py`, `platform/api/handlers/design.py`: 검수·저장·승인·프로세스.
- `platform/web/src/studio/`, `platform/web/src/views/AgentBuilder.tsx`: 사용자 흐름.
- `platform/tests/test_model_selection.py`, `test_studio_*.py`, `test_design_*.py`: 모델·라운드·정적 검수·반입 회귀 검증.
- 로컬 UI 테스트는 인증·WebSocket 응답을 명시적으로 대체해 상태 전달을 검사했다. 실제 모델 호출·라이브 배포 확인과 구분한다.
