# 시연 리허설 — 15분 스크립트와 체크리스트

접속 정보는 [데모 안내](./index.md)를 따른다. 자격 증명은 승인된 비공개 경로에서 확인하고 문서에 값을 남기지 않는다.
시작 전 **실제 그래프 백엔드**, **EKS 개인정보 처리 모델**, **Bedrock 설명 모델·호출 경로**를 각각 확인한다. Neptune으로 설명하는 고객 시연은 실제 Neptune을 사용한다(`SPEC.md` §10-1). 아래는 실행 절차이며 현재 배포의 통과 기록이 아니다.

## 오프닝 (30초)

> "말로 하면 반박당하는 세 가지를 화면으로 증명하겠습니다 — ① 벡터 RAG만으로는 부족하다,
> ② 개인정보는 프라이빗 경계 안에 두고 모델 호출만 익명화해서 내보낼 수 있다,
> ③ 사내 AI 자산은 Git처럼 승인 관리되어야 한다."

대시보드에서 **Single Boundary 지표**(경계 통과 토큰의 실측·추정 구분, 실제 모델 ID·차단 여부)를 먼저 짚는다 — "15분 뒤에 다시 봅니다."

## S1 — 규정 영향 분석 (4분)

1. 레일 "규정 영향 분석" → **시나리오 S1** 버튼 → **동시 실행**.
2. 좌측(Vector RAG)의 실제 검색 단계와 결과를 확인한다 → *"정확한 규정 청크를 찾았지만 '관련 문서를 정비하라' 수준입니다. 비교군을 약화시키지 않았습니다 — BM25+임베딩 하이브리드에 리랭커까지 정상 구현입니다."*
3. 우측(GraphRAG) → seed 신뢰도 배지 → counts 칩(실행 결과 확인; 이전 시연 기록은 상품 12·화면 39·부서 7·문서 7) → **근거 검증 통과** 배지: *"이번 검사에서 인용 노드 ID가 순회 결과에 있는지 확인합니다. 이 검사는 모든 설명 문장의 정확성까지 보증하지 않습니다."*
4. 하단 그래프에서 노드 하나 클릭(이웃 강조) → 더블클릭으로 온톨로지 탐색기 진입 → 노드 클릭으로 관계 확장 한 번.

핵심 멘트: *"같은 질문, 같은 모델 — 차이는 데이터의 구조입니다. 이것이 AI-Ready 데이터입니다."*

## S2 — 마이데이터 상담 (4분)

1. "마이데이터 상담" → 사용 가능한 **EKS 개인정보 처리 모델** 확인·선택 → **시나리오 S2** 버튼.
2. **질문 프라이버시 처리** 영수증 → ③ 정확 조회값 → ④ 계산엔진 **수식 단계**(합성 예제의 우대 상한 min(0.7, 0.6)) → ⑤ 정형 토큰화·독립 잔여 검사와 **실제 전달 페이로드**를 확인한다. 검사 0건은 설정된 탐지기의 결과이며 완전한 익명성 보장이 아니다.
3. 설명의 출력 Guardrails와 수치·Semantic 검증 결과를 확인한다. S2는 설명을 버퍼링해 출력 Guardrails 뒤에 전달한다. 현재 수치 검증은 이 전달 뒤에 수행하므로 모든 잘못된 수치가 표시 전에 차단된다고 설명하지 않는다.

핵심 멘트: *"수치의 기준은 계산엔진이며 LLM은 그 결과를 설명합니다. 실제 설명의 수치 검사 결과도 함께 확인합니다."*

질문은 입력 Guardrails보다 먼저 사설 EKS에서 처리한다. 정형 설명 자료에는 두 번째 sLLM 재작성을 하지 않으며, 개인정보 검사 실패는 중단한다. S2는 공용 캐시를 읽거나 쓰지 않는다(`SPEC.md` §4-3).

## S3 — Registry 반전 (3분)

1. "Agent Registry"에서 Button v2/v3 승인 상태 확인 → "화면 생성"에서 여신 심사 결과 화면 생성(승인 컴포넌트 목록 + 검증 게이트 결과 확인).
2. Registry에서 **Button v2를 Deprecated로 전환** → 재생성 → 코드가 v3 기반으로 바뀌는 것을 diff로 보여준다.

핵심 멘트: *"승인 상태가 소비 가능한 자산과 생성 결과를 바꿉니다."*

주 플랫폼 Registry의 상태·감사와 AgentCore 미러·CloudTrail은 별도 증거다. 기존 S3 컴포넌트 예제 검사는 React 작업실의 실제 소스·빌드·브라우저·릴리스 승인과 구분한다.

## S4 — Single Boundary 뷰 (2분)

- 방금 실행한 S1·S2가 타임라인에 쌓여 있다: traceId · VPC 잔류 항목 · 경계 통과 토큰 · **사용 모델 ID(global claude / gemma)** · Guardrails 판정 (§8-3 지표 5종).
- 배지 확인: *"저장: 서울 리전 / 추론: global 라우팅 — 그래서 익명화가 필수이고, 방금 요청들의 경계 통과 내역이 전부 실측으로 남았습니다."*

## S5 — Guardrails 차단 (2분)

- "마이데이터 상담"으로 돌아가 **S5 차단 시연** 버튼: "어떤 상품이 제일 돈 많이 벌어요?" → 실제 Bedrock Guardrails 정책 결과를 확인한다. EKS 처리 실패로 중단된 요청을 Guardrails 차단 성공으로 표시하지 않는다.
- Guardrails 로그 뷰에서 차단 이력 확인. *"목이 아니라 실제 Guardrails입니다 — 시뮬레이션 금지가 요구사항이었습니다."*

## 클로징 (30초)

가이드북 탭(또는 [인터랙티브 아키텍처](https://www.atomai.click/AgenticAI-Platform/platform-architecture.html) Play story)에서 이번 실행의 근거와 남은 확인을 정리한다. 교육용 설계 패턴과 실제 배포를 구분하며, IDC 연결이나 규제 적합성은 별도 검증 없이 주장하지 않는다.

## 시연 전 체크리스트 (SPEC §14)

아래 항목은 **시연 직전에 다시 확인**한다. 이전의 체크 표시와 테스트 수는 과거 기록(측정일 미기재)이었으며 현재 통과 증거가 아니다.

| 항목 | 확인할 증거 |
|---|---|
| `GRAPH_BACKEND=neptune`으로 전체 시나리오 동작 | 실제 백엔드 배지와 조회 결과 |
| S1: Vector RAG와 GraphRAG 비교 | 현재 검색 청크·영향 대상·순회 근거 |
| S2: 질문 제거·정형 토큰화·독립 검사 | 모델별 영수증과 실제 페이로드; 실패 시 중단·캐시 비사용 |
| S2: 계산 결과와 설명 수치 | 해당 버전 계산 테스트와 실제 수치 불일치 목록 |
| S3: Deprecated 전환 후 생성 결과 변경 | APPROVED 소비 목록과 재생성 결과 |
| S4: 경계 계측의 출처 확인 | `api/common/pii.py`, `tracing.py`와 현재 traceId; 누락은 0으로 간주하지 않음 |
| S5: Guardrails 실차단 | 현재 정책·버전의 `GUARDRAIL_INTERVENED` 결과 |
| F7: Reader의 내부 도구 호출 거부 | 별도 역할·배포 확인과 실제 IAM 거부 기록 |
| 응답·진행 표시 지연 | 실제 지연 측정; S2는 검증 전 토큰 노출 금지 |
| 리셋 버튼으로 시연 상태 복구 | 의도한 Registry 시연 레코드와 대화 범위 확인 |
| 실제 고객데이터·상품명·조항 없음 | 고정 시드와 가상 개인정보 검사 예제의 범위 확인 |

## 비상 대응

- **Bedrock 무응답/스로틀**: 지원되는 비개인 시나리오만 "캐시 응답" 배지를 붙여 재생할 수 있다. **S2는 공용 이벤트 캐시를 읽거나 쓰지 않으며 개인정보 검사 실패 시 중단한다.** 장애를 해결한 뒤 다시 실행한다.
- **시연 중 실수**: 우측 상단 **⟲ 시연 리셋** — Registry 시연 레코드가 기준선으로 복원된다.
- **이전 URL**: <https://d15n7n9ypt87h8.cloudfront.net/>는 과거 배포 기록이다. 가용성·버전 확인 없이 현행 서비스의 예비 경로로 약속하지 않는다. 다른 버전이나 자매 데모를 사용하면 그 범위를 밝힌다(`SPEC.md` §12 항목 2).
- **세션 만료**: 현재 인증 상태를 확인하고 재로그인한다. 제품별 토큰·세션 처리 방식이 같다고 가정하지 않는다.
