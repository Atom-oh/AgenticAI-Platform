# Studio 모델 선택과 디자이너용 검증 상태 정리

**목표:** 금융망 운영 전제를 유지하면서 Astra·Fable을 실제 호출까지 선택 가능하게 하고, 정적 시안 검수와 실행 검증을 혼동하는 표시를 바로잡는다.

**근거:** 2026-09-10 사용자 제공 구현 점검, 현재 저장소, 같은 날 조회한 서울 리전 Bedrock foundation model / inference profile 목록.

## 변경 범위

- 허용 모델의 공통 카탈로그: 기존 Sonnet·Opus에 GPT-6 Astra, Claude Fable 5·5.1 추가.
- Studio 생성·선택 요소 수정·리뷰와 프로세스 생성에서 선택 모델을 실제 호출에 전달. 기본 모델을 프로세스 전역에서 바꾸지 않는다.
- 에이전트 빌더의 카탈로그와 서버 검증에 같은 허용 목록 적용.
- 모델별 실제 호출 ID와 실행 결과를 기록. 잘못된 모델을 기본 모델로 조용히 대체하지 않는다.
- 디자이너에게 정적 시안/정적 검수/동작 미검증을 구분해 표시하고, 연결 정보와 반복 설정은 보조 정보로 정리한다.
- 기존·통합 갤러리의 조회 범위를 명시하며, 과거 사람 승인을 새 기능 검증 통과로 전환하지 않는다.
- 비필수 미판정도 자동 검수 통과에서 제외하고, 최종 라운드 선택은 통과 여부를 점수보다 우선한다.
- 기존 독립 Studio의 모델 목록과 플랫폼의 새 모델 선택을 라이브에서 확인한다.

## 운영 제약

- 2026-09-11 사용자 정정으로 운영 전제를 갱신했다. 3호망에서도 Figma 접속이 불가하며,
  외부에서 전달받은 산출물을 정해진 반입 절차로 가져온다. Studio의 Figma 직접 연결은 추가하지 않는다.
- 모델 호출은 기존 익명화 게이트와 허용된 Amazon Bedrock 경로만 사용한다.
- 사내 MCP에 실제로 없는 컴포넌트·규칙·도구를 구현된 것으로 표시하지 않는다.
- 새 파일 반입 시스템, 실제 은행 React 패키지 연결, 시각·실행 검증기 전체는 이번 모델 선택 작업의 완료 주장에 포함하지 않는다.
- 기존 시안·승인·부모 관계를 삭제하거나 새 검수로 자동 승격하지 않는다.

## 실행과 검증

1. 기존 Studio·게이트·모델 어댑터·에이전트 핸들러 테스트를 실행한다.
2. 선택 모델의 생성/리뷰/수정 전달, 허용 목록 밖 모델 거부, 동시 요청 간 모델 격리, PII 게이트 유지 테스트를 먼저 추가한다.
3. 공통 카탈로그와 호출별 Bedrock 모델 선택을 구현하고 관련 테스트를 통과시킨다.
4. Studio와 에이전트 빌더에 모델 선택을 연결하고, 오류·로딩·실행 중 상태를 처리한다.
5. 검수 상태 문구와 미판정/라운드 선택을 보정하고 회귀 테스트를 실행한다.
6. Python 관련 테스트와 전체 테스트, TypeScript 검사, 프론트 빌드를 실행한다.
7. 모델 선택과 검수 상태의 브라우저 검증 후, 변경한 API·Studio 워커·프론트를 배포한다. 기존 시안의 S3 경로를 삭제하지 않는다.
8. 라이브에서 Astra·Fable 선택과 모델별 실제 호출, 저장된 모델 ID를 확인한다. 새 테스트 시안을 제품 승인으로 처리하지 않는다.
9. 완료한 수정과 미완료된 입력·매핑·실행 검증·이력 통합을 구분해 비개발자 디자이너 관점의 판단을 남긴다.
