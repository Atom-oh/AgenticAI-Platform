# 한국 금융 규제

::: danger 이 챕터는 법률자문이 아니다
이 챕터는 플랫폼 엔지니어링 관점에서 규제 지형을 정리한 기술 문서이며, 법률자문(legal advice)이 아니다. 실제 서비스 출시·인프라 변경 전에는 반드시 사내 준법감시(compliance) 조직과 금융규제 전문 법률가의 검토를 받아야 한다. 규제는 계속 변한다 — 이 챕터의 모든 내용은 **2026-08-31 작성 시점** 기준이며, 그 이후의 개정·유권해석은 반영되어 있지 않다.
:::

::: tip 이 장에서 얻는 것
- 2024-08-13 「금융분야 망분리 개선 로드맵」 이후의 규제 완화 타임라인과 각 단계의 법적 근거
- 생성형 AI·SaaS를 금융회사 내부망에서 쓸 수 있는 세 가지 경로(혁신금융서비스, 규정 예외, 시행세칙 개정)와 각각의 조건
- 망분리 완화와 **별개로** 살아있는 개인정보보호법·신용정보법 제약의 구분법
- 이 지형이 Agentic AI 플랫폼 설계에 강제하는 아키텍처 결정 — 하이브리드 구성, CRIS 지리 프로파일, 승인 게이트
- 규제 변경을 운영 항목으로 추적하는 체크리스트
:::

## 왜 문제가 되는가

한국 금융권의 망분리(network separation) 규제는 2013년 대규모 전산망 마비 사태 이후 도입된 물리적 망분리 의무를 근간으로 한다. 전자금융감독규정 제15조 제1항 제3호는 "내부통신망과 연결된 내부 업무용시스템은 인터넷(무선통신망 포함) 등 외부통신망과 분리·차단 및 접속 금지"를 요구해 왔다. 이 규정 하나가 Agentic AI 플랫폼에 미치는 영향은 결정적이다:

- **상용 LLM API는 전부 외부통신망이다.** Amazon Bedrock, OpenAI, Anthropic API 호출은 모두 인터넷 구간을 거친다. 내부 업무용시스템에서 이들을 직접 호출하는 것은 원칙적으로 규정 위반이었다.
- **SaaS 기반 개발 도구도 마찬가지다.** GitHub Copilot, Slack, Notion 같은 도구가 내부망에서 차단되면서 개발 생산성과 인재 확보 양면에서 비용이 발생했다.
- **에이전트 아키텍처는 외부 호출의 연쇄다.** Tool use, RAG, MCP 서버 연동은 모두 네트워크 경계를 넘나드는 호출 그래프를 만든다. "외부망 접속 금지"라는 단일 규칙이 에이전트 플랫폼의 거의 모든 구성 요소와 충돌한다.

2024년 8월 13일 금융위원회는 「금융분야 망분리 개선 로드맵」을 발표하며 방향을 바꿨다. 김병환 금융위원장은 "클라우드, 생성형 AI 등 급변하는 IT 환경변화에 대응하기 위해 보다 효과적인 망분리 개선 방안이 필요한 시점이며, 특히 모든 정책은 글로벌 스탠다드 관점에서 정비해 나간다는 기조 하에, 우리나라에만 존재하는 대표적인 **갈라파고스 규제**를 과감하게 개선할 필요가 있다"고 밝혔다([금융위원회 보도자료, 2024-08-13](https://www.fsc.go.kr/no010101/82885)). 로드맵의 골자는 세 가지다: **① 금융회사의 생성형 AI 활용 허용, ② 클라우드(SaaS) 이용 범위 대폭 확대, ③ 연구·개발 환경 개선**. 다만 금융위는 급격한 완화가 아니라 단계적 개선을 명시했고, 실제로 이후 2년간 규제 샌드박스 → 감독규정 개정 → 시행세칙 개정의 순서로 단계가 진행됐다.

플랫폼 엔지니어에게 이것이 "문제"인 이유는 완화가 **비동기적·부분적**이기 때문이다. 생성형 AI 활용은 혁신금융서비스 지정(2년 + 연장, 부가조건 부착)이라는 시한부 특례로 먼저 열렸고, 연구·개발망은 감독규정 개정으로, 내부 업무망 SaaS는 시행세칙 개정으로 각각 다른 시점에 다른 조건으로 열리고 있다. 아키텍처를 어느 단계 기준으로 설계하느냐에 따라 재작업 비용이 크게 달라진다.

### 경로 1 — 혁신금융서비스 (규제 샌드박스)

금융위원회는 2024-11-27 정례회의에서 생성형 AI를 활용한 9개 금융회사의 10개 서비스를 혁신금융서비스로 첫 지정했다. 신청 기간(2024-09-16~27) 동안 74개사가 141건을 망분리 규제 특례로 신청했고, 김병환 위원장은 "신청이 141건이나 될 정도로 많이 접수되었고, 이를 통해 금융회사들의 망분리 규제개선에 대한 열망과 혁신에 대한 강한 의지를 느낄 수 있었다"고 언급했다([금융위 보도자료](https://www.fsc.go.kr/no010101/83554)).

플랫폼 관점의 핵심 속성:

- **시한부다.** 지정 기간(기본 2년, 연장 가능)이 끝나면 상시 규범으로 전환되거나 특례가 소멸한다. 샌드박스 특례에 의존한 아키텍처는 특례 종료 시나리오를 반드시 설계에 포함해야 한다.
- **부가조건이 붙는다.** 지정서에 명시된 보안 통제(데이터 범위, 접근 통제, 사고 대응)가 사실상 아키텍처 요구사항이 된다.
- **심사 대기열이 있다.** 141건 신청 대비 첫 지정 10건 — 지정은 순차적으로 진행되므로 리드타임을 프로젝트 일정에 반영해야 한다.

### 경로 2 — 전자금융감독규정 제15조 제1항 제3호 가목 (연구·개발 예외)

2024-12-24 전자금융감독규정 일부개정(금융위원회 고시 제2024-60호)으로 제15조 제1항 제3호에 단서(가목)가 신설되어, **연구·개발 목적 내부통신망**에 대해 외부망 분리·차단 의무의 예외 — 즉 물리적 망분리 대신 **논리적 망분리**(logical separation) — 가 상시 규범으로 허용됐다([금융위 고시](https://www.fsc.go.kr/po040200/83713), [국가법령정보센터 — 전자금융감독규정](https://www.law.go.kr/행정규칙/전자금융감독규정)). 조건은 대략 다음과 같이 요약된다:

- 자체 위험성 평가(risk assessment)를 실시하고,
- 규정 별표에서 정한 **망분리 대체 정보보호통제**를 적용하며,
- 정보보호위원회 승인을 거칠 것.
- 같은 개정에서 연구·개발 목적 예외 적용 시 **가명처리된 개인신용정보**의 활용도 허용됐다.

> ⚠️ 비공식 출처 기반 — 공식 문서 교차확인 필요
> 가목의 조문 원문 표현과 별표 번호(별표 7로 알려짐), 대체통제의 세부 항목은 법률사무소 뉴스레터·보안업체 해설 등 2차 자료로 확인한 것이다. 실제 적용 전에 [국가법령정보센터](https://www.law.go.kr/행정규칙/전자금융감독규정)에서 현행 조문 원문과 별표를 직접 대조하라.

엔지니어링 함의: 연구·개발망(R&D VPC)에서는 Bedrock 등 외부 LLM API 호출이 논리적 망분리 통제 하에 합법적으로 가능해졌다. 단, "연구·개발 목적"이라는 용도 제한이 있으므로 이 망에서 만든 것을 **운영(production) 트래픽으로 슬쩍 승격시키는 순간 예외 요건을 벗어난다.** R&D망과 운영망의 경계는 IAM·네트워크·배포 파이프라인 수준에서 기술적으로 강제되어야 한다.

### 경로 3 — 시행세칙 개정 (내부 업무망 SaaS)

금융위·금감원은 2026-01-19 보도자료에서, 금융회사가 **내부 업무망에서 SaaS를 혁신금융서비스 심사 없이** 이용할 수 있도록 하는 전자금융감독규정시행세칙 개정안의 사전예고(2026-01-20 ~ 02-09, 20일간)를 발표했다([금융위 보도자료](https://www.fsc.go.kr/po010101/86080)). 핵심 조건과 범위:

- 침해사고 대응기관의 평가를 거친 SaaS 이용, 접속 단말기 보호대책, 안전한 인증방식 적용 등 **보안 규율 준수가 전제**다.
- 문서작성·화상회의·가상 업무공간·인사관리 등 **사무관리·업무지원용** SaaS가 대상이다. 고객 정보가 직접 연계되는 코어뱅킹·대고객 서비스 영역은 여전히 망분리 규제가 적용되며, 그 영역의 SaaS 활용은 별도의 샌드박스 절차가 필요하다.
- 보도자료는 "생성형 AI 등 추가적인 망분리 개선과제도 최대한 신속하게" 진행하겠다고 예고했다 — 즉 생성형 AI 서비스 도입에 대해서도 혁신금융서비스 심사 없는 망분리 규제 예외 적용이 추진될 것으로 읽힌다.

::: warning 미정착 영역
작성 시점(2026-08-31) 기준으로 확인된 것은 **사전예고(2026-01-20~02-09)** 사실과 그 내용이다. 시행세칙 개정은 **사전예고 → 규제개혁위원회 심사** 등의 절차를 거쳐 확정·시행되며, 최종 확정 여부·시행일·확정 조문이 사전예고안과 동일한지는 이 챕터에서 확인하지 못했다. 생성형 AI에 대한 "신속한 예외 적용" 역시 예고 수준의 언급이다. 도입 의사결정 전에 시행세칙의 현행 조문과 금감원 공시를 직접 확인하라.
:::

### 망분리 완화 ≠ 데이터 규제 완화

가장 흔한 오해: 망분리가 풀리면 데이터도 보낼 수 있다는 착각. **개인정보보호법과 신용정보법(신용정보의 이용 및 보호에 관한 법률)상의 PII·개인신용정보 처리 제약은 망분리 완화와 별개의 법률로 독립적으로 적용된다**([개인정보보호법 — 국가법령정보센터](https://www.law.go.kr/법령/개인정보보호법), [신용정보법 — 국가법령정보센터](https://www.law.go.kr/법령/신용정보의이용및보호에관한법률)). 네트워크 경로가 합법이어도:

- 개인정보의 제3자 제공·처리위탁·국외이전은 각각의 법적 근거(동의, 계약, 고지 등)가 필요하다.
- 개인신용정보는 신용정보법상 더 엄격한 처리·보관·파기 규율을 받는다.
- 연구·개발 예외에서 허용된 것도 **가명처리된**(pseudonymized) 개인신용정보다 — 원본 PII가 아니다.

즉 플랫폼에는 네트워크 계층의 통제(망분리 대체통제)와 데이터 계층의 통제(PII detection, masking, 가명처리 파이프라인)가 **둘 다** 필요하다. 프롬프트와 RAG 컨텍스트에 PII가 섞여 외부 LLM으로 나가는 것을 막는 것은 망분리 규제가 아니라 개인정보보호법·신용정보법 이슈다.

| 운영(production)에서 고객 대상 생성형 AI 서비스 | 혁신금융서비스 지정 신청 | 작성 시점 기준 대고객 영역에서 외부 LLM을 쓰는 유일한 합법 경로 | 심사 리드타임, 부가조건, 특례 시한(종료 시나리오 설계 필요) |
| 모델 평가·프롬프트 실험·PoC | 제15조 연구·개발 예외 (논리적 망분리 R&D망) | 상시 규범, 샌드박스 불필요, 가명정보 활용 가능 | "연구·개발 목적" 한정 — 운영 승격 시 경로 재설계 필요 |
| 사내 생산성 도구 (문서·협업·개발 SaaS) | 시행세칙 개정 경로 (확정 시) + 보안 규율 준수 | 심사 없는 상시 허용이 목표인 경로 | 작성 시점 기준 사전예고 단계 — 확정 전 도입은 리스크 |
| 원본 고객 PII·신용정보를 컨텍스트에 포함해야 하는 워크로드 | 온프레미스/내부망 self-hosted 모델 또는 데이터 비식별화 후 외부 호출 | 망분리와 무관하게 개인정보보호법·신용정보법이 국외이전·제3자 제공을 제약 | self-hosted는 모델 품질·운영 비용 부담, 비식별화는 응답 품질 저하 |
| 규제 확정 전인데 아키텍처를 지금 결정해야 함 | 하이브리드 아키텍처 ([상세](/12-security-korea/hybrid-architecture)) | 어느 쪽으로 확정되든 재작업 최소화 | 초기 구축 복잡도 증가 |
| Bedrock 호출의 데이터 처리 위치를 보장해야 함 | CRIS 지리 프로파일 고정 ([상세](/08-scaling-cost/bedrock-inference-tiers)) | cross-region 라우팅이 규제상 허용 지역을 벗어나는 것을 방지 | 단일 지역 고정 시 처리량·가용성 헤드룸 감소 |

## 실패 모드

| 증상 | 근본 원인 | 확인 방법 | 해결 |
|---|---|---|---|
| 감독 검사에서 R&D망 예외 요건 미충족 지적 | R&D망에서 개발한 에이전트가 운영 트래픽을 처리 중 ("목적 외 사용") | R&D VPC의 트래픽 소스 분석 — 운영 서비스 IP/role이 호출자에 있는지 | R&D/운영 계정 분리, SCP·리소스 정책으로 cross-환경 호출 차단 |
| 특례 종료 통보 후 서비스 중단 위기 | 혁신금융서비스 시한(2년+연장)을 아키텍처가 가정하지 않음 | 지정서의 지정 기간과 서비스 로드맵 대조 | 특례 종료 시 내부망 fallback 경로를 처음부터 설계 (하이브리드) |
| 프롬프트 로그에서 주민등록번호·계좌번호 발견 | 망분리 통과 = 데이터 규제 통과로 오인, PII 필터 부재 | 아웃바운드 프롬프트 로그에 PII detection 배치 실행 | LLM gateway 계층에 PII masking 강제, [시맨틱 캐시 승인 게이트](/04-caching/semantic-vs-exact-caching) 연동 |
| Bedrock 응답 지연 해소하려 CRIS 켰더니 준법감시 경보 | cross-region 프로파일이 데이터를 허용 외 지역으로 라우팅 | CloudTrail의 `inferenceProfileArn`과 실제 처리 리전 확인 | 지리 프로파일 고정 ([Bedrock inference tiers](/08-scaling-cost/bedrock-inference-tiers)) |
| 사전예고안 기준으로 구축한 SaaS 연동이 확정 조문과 불일치 | 사전예고 → 규제개혁위 심사 과정에서 조문 변경 | 확정 고시문과 구축 당시 참조한 예고안 diff | 규제 추적을 분기별 운영 항목화, 확정 전 도입분은 feature flag로 격리 |
| 정보보호위원회 승인 없이 논리적 망분리 운영 | 예외 요건(위험성 평가 + 대체통제 + 위원회 승인)을 체크리스트 없이 부분 이행 | 승인 의결 기록·위험성 평가 보고서 존재 여부 | 예외 적용 전 3요건을 게이트로 하는 변경관리 프로세스 |

## 안티패턴

- ❌ "망분리 풀렸으니 고객 데이터도 API로 보내면 된다" → ✅ 네트워크 규제(전자금융감독규정)와 데이터 규제(개인정보보호법·신용정보법)를 별도 통제 계층으로 각각 충족한다.
- ❌ R&D 예외망에서 만든 에이전트를 그대로 운영에 승격 → ✅ 운영 전환 시점에 혁신금융서비스 지정 또는 (확정 시) 시행세칙 경로로 법적 근거를 갈아끼우는 승격 절차를 파이프라인에 내장한다.
- ❌ 사전예고·언론 보도를 "시행 중인 규제"로 간주하고 구축 → ✅ 사전예고 → 규제개혁위 심사 → 확정 고시의 단계를 구분하고, 확정 고시문 기준으로만 운영 전환한다.
- ❌ 혁신금융서비스 특례를 영구 인프라의 전제로 삼기 → ✅ 특례는 시한부 — 종료 시 내부망 fallback이 있는 하이브리드 구성을 기본값으로 한다.
- ❌ 규제 대응을 프로젝트 단위 일회성 검토로 처리 → ✅ 분기별 규제 추적을 플랫폼 운영 루틴(on-call runbook 수준)으로 제도화한다.
- ❌ 준법감시 부서에 아키텍처 다이어그램 없이 "LLM 씁니다"로 보고 → ✅ 데이터 흐름도(어떤 데이터가 어떤 경계를 넘는지)를 기준으로 규제 매핑 문서를 유지한다.

## 계측 (SLI)

규제 준수는 감사 시점의 스냅샷이 아니라 상시 측정 가능한 신호로 만들어야 한다. 플랫폼이 노출해야 할 최소 지표:

- **외부 LLM 호출 커버리지**: 전체 외부 모델 호출 중 승인된 경로(지정된 gateway, 고정된 inference profile)를 거친 비율. 목표 100%, 위반은 즉시 alert. VPC Flow Logs + gateway 액세스 로그로 계측.
- **PII 유출 차단율**: 아웃바운드 프롬프트/컨텍스트에서 PII detector가 탐지→마스킹한 건수와, 사후 감사에서 발견된 미탐(false negative) 건수. 미탐은 SEV 이슈로 취급.
- **지리 프로파일 준수율**: Bedrock 호출 중 허용 리전에서 처리된 비율 — CloudTrail 기반. CRIS 설정 변경이 이 지표를 흔들면 배포를 차단한다.
- **환경 경계 위반 시도**: R&D망 리소스에 대한 운영망 principal의 호출 시도 건수 (SCP deny 로그). 0이 아니면 승격 절차 우회 시도의 신호다.
- **규제 추적 신선도**: 마지막 규제 리뷰(금융위 보도자료·법제처 조문 확인) 이후 경과 일수. 90일 초과 시 운영 대시보드에 경고.
- **특례 잔여 기간**: 혁신금융서비스 지정 만료까지 남은 일수를 대시보드에 노출 — 만료 180일 전 fallback 리허설을 트리거.

## 체크리스트

**법적 근거 확정**
- [ ] 각 워크로드(대고객 / 내부 업무 / R&D)가 세 경로 중 어느 법적 근거에 기대는지 문서화했다
- [ ] 혁신금융서비스 의존 워크로드의 지정 기간·부가조건을 아키텍처 요구사항으로 등록했다
- [ ] R&D 예외 적용 전 3요건(자체 위험성 평가 → 대체 정보보호통제 → 정보보호위원회 승인)을 모두 이행하고 기록을 남겼다
- [ ] 시행세칙 경로 의존 항목은 사전예고안이 아닌 **확정 고시문**을 확인한 후에만 운영 전환한다

**데이터 계층**
- [ ] 외부 LLM으로 나가는 모든 경로에 PII detection/masking이 gateway 수준에서 강제된다
- [ ] 가명처리 파이프라인이 신용정보법 기준을 충족하는지 준법감시 확인을 받았다
- [ ] 국외이전이 발생하는 데이터 흐름을 식별하고 각각의 법적 근거를 매핑했다

**네트워크·인프라 계층**
- [ ] R&D망과 운영망이 계정·IAM·SCP 수준에서 분리되고 cross-호출이 기술적으로 차단된다
- [ ] Bedrock 호출이 지리 고정 inference profile만 사용하도록 IAM 조건으로 강제된다 ([상세](/08-scaling-cost/bedrock-inference-tiers))
- [ ] 특례 종료·규제 회귀 시나리오에 대한 내부망 fallback 경로가 존재하고 리허설된다 ([하이브리드 아키텍처](/12-security-korea/hybrid-architecture))
- [ ] 캐시된 LLM 응답의 재사용에 승인 게이트가 있다 ([시맨틱 캐시](/04-caching/semantic-vs-exact-caching)) — 규제 요건 변경 시 캐시 무효화 경로 포함

**운영 루틴**
- [ ] **분기별 규제 추적**이 운영 캘린더에 등록되어 있다: 금융위 보도자료, 금감원 공시, 법제처(국가법령정보센터) 현행 조문 확인
- [ ] 사전예고 중인 개정안(예: 시행세칙 SaaS 개정)의 규제개혁위 심사·확정 여부를 추적하는 담당자가 지정되어 있다
- [ ] 규제 매핑 문서(데이터 흐름 ↔ 적용 법령)가 아키텍처 변경 시 함께 갱신된다
- [ ] 이 챕터 작성 시점(2026-08-31) 이후의 변경사항을 스스로 확인했다
